# 7. Следить за процессом

Каждый видит, где что стоит, а команда видит, где страдает процесс.

```bash
sdlc next --me                                  # что ждёт вас, с командой
sdlc explain --change basic-arithmetic          # почему изменение там, где оно есть
sdlc health                                     # находки о потоке, качестве, дисциплине и настройке
sdlc report --format html --out report.html     # страница дашборда
sdlc audit                                      # сроки, ожидания, возвраты, участие людей
sdlc log --limit 20                             # каждое решение с версией sdlc, которая его записала
```

- `sdlc health` даёт находки с фактами и рекомендацией, но никогда не общий балл. `/sdlc:health` объясняет их и
  оформляет улучшения в бэклог, а порядок ставит человек.
- Когда появляется плохая находка (нет команд проверки, принуждение выключено, просроченный гейт), начало сессии
  агента сообщает об этом одной строкой, а приёмники событий команды получают `health.degraded`.
- `sdlc audit` сравнивает по каждому изменению решения, которые планировал трек, с тем, что было: утверждения,
  возвраты, перехваты, снятия, ответы.

Это весь цикл: спланировать, утвердить, собрать, проверить, сделать ревью, выпустить, заархивировать и оглянуться.
Спрашивайте агента о чём угодно по дороге: его ответы берутся из статей `sdlc guide`.
