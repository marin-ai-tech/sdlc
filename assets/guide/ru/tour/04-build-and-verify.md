# 4. Сборка и проверка с доказательствами

Когда план утверждён, агент собирает (`/sdlc:build`): идёт по `tasks.md`, по ходу запускает проверки и называет в
коммитах изменение и задачу. До утверждения плана хук запрещает правки кода.

Проверка состоит из двух частей:

```bash
sdlc verify --change basic-arithmetic          # запускает verify.commands, пишет доказательства в verification.md
sdlc verify --check --change basic-arithmetic  # у каждого сценария спецификации есть строка поведенческой проверки
```

- Доказательства буквальные: команды, коды выхода, вывод, коммит. Они привязаны к коду: изменили файл — гейт verify
  ждёт нового запуска.
- Независимый субагент-проверяющий проходит каждый сценарий и сообщает, что увидел; агент записывает это в
  «Behavioral verification». Что не запускали — в «Not run / limits»; скриншоты — в папку `verification/` изменения.
- Проверка не прошла — исправляют код, а не тест.

Для бага порядок такой: сначала тест. Агент пишет падающий тест и блокирует тесты, чтобы исправление меняло код:

```bash
sdlc tests lock --change fix-rounding
```

Снять блок — решение человека (`sdlc tests unlock`).

Дальше: ревью.
