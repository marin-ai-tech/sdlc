# 3. Замысел, спецификация и план — каждый утверждает человек

Агент пишет, человек утверждает. Утверждение привязано к содержимому: изменили файл — утверждение устарело.

1. **Замысел** (`/sdlc:intent`): проблема, результат, кого это касается, и открытые вопросы. Вопросы агент оставляет
   людям; Алиса отвечает на них сама и утверждает:

   ```bash
   sdlc answer 1 --change basic-arithmetic --text "Кассиры на кассе"
   sdlc approve intent --change basic-arithmetic
   ```

2. **Спецификация** (`/sdlc:spec`): предложение, дельты спецификаций с требованиями и сценариями, дизайн. OpenSpec
   строго их проверяет (`sdlc validate`). Алиса утверждает спецификацию.
3. **План** (`/sdlc:plan`): какие файлы меняются, порядок работы, доказательство, откат и задачи. Боб, инженер,
   утверждает его: `sdlc approve plan --change basic-arithmetic`.

Если что-то раньше было не так, человек возвращает изменение с причиной и заметкой:

```bash
sdlc rework spec --change basic-arithmetic --reason missing-requirement --note "Скажите, что показывает 10 / 0"
sdlc explain --change basic-arithmetic        # почему изменение здесь и что его разблокирует
```

Последующие утверждения перестают учитываться; спецификация должна измениться, прежде чем её утвердят снова (или
человек объяснит в `--note`, почему менять нечего). Утверждают всегда в своём терминале: в сессии агента
`sdlc approve` отказывает.
