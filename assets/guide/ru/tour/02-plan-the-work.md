# 2. Спланировать работу в бэклоге

До любого изменения команда записывает, чего хочет: эпики и пункты в `openspec/backlog.md`. Один пункт потом
становится одним изменением OpenSpec.

```bash
sdlc backlog epic add "Калькулятор кассы" --goal "Кассир складывает, вычитает, умножает и делит на кассе"
sdlc backlog add "Базовая арифметика" --epic E1 --kind feature --outcome "Четыре действия на кассе"
sdlc backlog list
sdlc explore division-by-zero                     # исследование до замысла, если нужно
```

- Агент может добавлять пункты и черновики; порядок бэклога решает человек (`sdlc backlog move`), как и отказ от пункта.
- Исследование (`openspec/explorations/<slug>.md`) — место, где идею проверяют на прочность, пока никто не пишет
  замысел.
- Когда ничего не идёт, `sdlc next` предлагает следующий готовый пункт, а `sdlc backlog start B1` создаёт изменение с
  черновиком замысла.

```bash
sdlc backlog start B1
sdlc status
```

`sdlc status` показывает все активные изменения: этап (план, дизайн, сборка, проверка, выпуск), гейты и кто действует
дальше.

Дальше: замысел, спецификация и план.
