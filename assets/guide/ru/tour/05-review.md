# 5. Ревью по политике команды

Субагент-ревьюер в чистом контексте читает изменения по `REVIEW.md` (`/sdlc:review`): корректность, безопасность,
линзы команды. Замечания попадают в `review.md` с важностью, статусом и проходом, к которому относятся.

```bash
sdlc review context --change basic-arithmetic   # изменения, политика и отклонение от плана
sdlc review check --change basic-arithmetic     # открытые блокирующие замечания и покрытие проходов и линз
sdlc defer add "Деление на ноль показывает ошибку" --why "Пока это делает касса" --change basic-arithmetic --finding F2
```

- Открытое замечание `important` блокирует гейт ревью; его исправляют или откладывают с причиной в реестр отложенной
  работы.
- Кэрол, владелец кода, утверждает ревью: `sdlc approve review --change basic-arithmetic`. Боб не может утвердить ревью
  своего кода: разделение обязанностей проверяется по авторам коммитов.
- `sdlc approve review --preview` показывает, что Кэрол собирается утвердить: файлы, открытые замечания, проверку.

После утверждения sdlc печатает готовый `git commit` с трейлером `SDLC-Approval`, чтобы коммит можно было связать с
решением.
