# 6. Выпуск и архив

Если гейт выпуска включён, агент готовит `release.md` (`/sdlc:release`): список изменений, раскатку по окружениям,
контрольные границы, откат. Его утверждает ответственный за выпуск; в этот момент запускаются проверки выпуска,
настроенные как инструменты MCP.

```bash
sdlc approve release --change basic-arithmetic
sdlc approvals verify                          # подписанные утверждения и их коммиты
sdlc archive basic-arithmetic --yes            # ещё раз проверяет все гейты и сливает дельты спецификаций
```

- Архив сливает дельты спецификаций изменения в живые спецификации (`openspec/specs/`): следующее изменение начинается
  с того, что продукт делает на самом деле.
- Пункт бэклога изменения закрывается, и `sdlc next` предлагает следующий готовый.
- Архивировать мимо открытого гейта может только человек и с заметкой (`--force`); это видно в аудите и в здоровье
  проекта.

Остальные процессы демо коротко: тревога становится новым замыслом (`/sdlc:triage`), отклонённая идея
останавливается рано (`sdlc reject`), мелкое исправление идёт по треку lite (`sdlc track set lite`), а артефакты
планирования BMAD можно импортировать (`sdlc import bmad`).
