# Исправление ошибки

Исправление идёт по протоколу: воспроизвести, доказать падающим тестом, исправить и убедиться, что система тестов
поймает такую ошибку в следующий раз.

## Шаги

1. `sdlc new fix-<имя> --kind bugfix` (часто на облегчённом треке: `sdlc guide tracks`).
2. Агент пишет тест, который **падает по правильной причине**, и записывает план.
3. Человек утверждает план: `sdlc approve plan --change <id>`.
4. Тесты блокируются, чтобы исправление нельзя было сделать правкой тестов:

```bash
sdlc tests lock --change fix-rounding
```

5. Агент исправляет код. Пока тесты заблокированы, хук запрещает агенту правки тестовых файлов
   (`enforcement.test_paths`), и в режиме warn тоже.
6. `sdlc verify --change <id>` записывает доказательства: упавший тест теперь проходит.
7. Человек снимает блокировку, когда работа закончена: `sdlc tests unlock --change <id>` (команда человека).

## Зачем блокировать тесты

Самый быстрый способ сделать красный тест зелёным — поправить тест. Блокировка отнимает эту возможность у агента,
и доказательство значит то, что говорит.

## После исправления

Спросите агента, какой слой должен был поймать ошибку и почему не поймал, и добавьте эту проверку (сценарий, фикстуру,
защиту). Отложенную работу — в реестр: `sdlc defer add "…" --why "…" --change <id>`.
