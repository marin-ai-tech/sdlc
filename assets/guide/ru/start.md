# С чего начать

sdlc ведёт жизненный цикл из плейбука Anthropic по AI-native SDLC прямо в агенте разработки. Агент пишет артефакты и
код. **Решения принимают люди**: утверждения, исключения гейтов, возвраты на доработку, релиз.

## Первые шаги

1. `sdlc init` в проекте, затем `sdlc doctor` — проверить установку.
2. Начать изменение: опишите работу агенту (он запустит процесс intent) или выполните `sdlc new <имя>`. Если есть
   бэклог — `sdlc backlog start <B-id>`.
3. В любой момент спросите `sdlc next`: он называет следующий шаг и того, кто его делает (агент или человек, по имени —
   если есть `openspec/roles.yaml`).
4. Когда нужен человек, выполните команду из `sdlc next` **в своём терминале**.

## Кто что делает

| Агент | Человек |
|---|---|
| пишет намерение, спецификации, дизайн, план, задачи, код | утверждает гейты (`sdlc approve`) |
| запускает `sdlc verify` и записывает доказательства | исключает или отклоняет (`sdlc waive`, `sdlc reject`) |
| проводит ревью по проходам и записывает находки | возвращает на доработку (`sdlc rework`), забирает изменение (`sdlc takeover`) |
| готовит описание релиза | разрешает релиз |

Ответ в чате — никогда не утверждение: агент утвердить не может, а команда с `!` в чате агента выполняется в оболочке
агента и тоже отклоняется.

## Где что лежит

- `openspec/changes/<id>/` — артефакты изменения и его запись `.sdlc.yaml` (пишет только CLI).
- `openspec/sdlc.yaml` — гейты, проверки, контроль. Агент его править не может.
- `openspec/backlog.md` — запланированная работа, `openspec/roles.yaml` — кто какую роль держит.

Дальше: `sdlc guide lifecycle`.
